# Kingdom — operations runbook

- Environment: ChromeOS Crostini (Penguin container), user `techcorp2024`
- Workspace: `~/kingdom` (native btrfs disk — never relocate onto `/mnt/chromeos/*`)
- Remote: `git@github.com:TechCorp25/kingdom.git` (branch `main`)
- Stack: Python 3.12+ · uv · FastAPI · SQLAlchemy 2 async (asyncpg) · Alembic · FastMCP
- Database: local PostgreSQL (development); Railway (deployment, later)

---

## 1. First-time setup (rebuild reference)

```bash
curl -fsSL https://astral.sh/uv/install.sh | sh      # then re-open terminal
sudo apt install -y postgresql nano zip unzip        # Crostini ships none of these
cd ~/kingdom
./scripts/bootstrap/bootstrap.sh                     # tree + uv sync + .env + git
```

## 2. Database setup (local Postgres)

```bash
sudo service postgresql start                        # Crostini uses `service`, NOT systemctl
PW=$(python3 -c "import secrets; print(secrets.token_hex(16))")
sudo -u postgres psql \
  -c "CREATE ROLE kingdom LOGIN PASSWORD '$PW';" \
  -c "CREATE DATABASE kingdom OWNER kingdom;"
sed -i "s|^DATABASE_URL=.*|DATABASE_URL=postgresql+asyncpg://kingdom:$PW@localhost:5432/kingdom|" ~/kingdom/.env
uv run alembic upgrade head                          # create projects/tasks/memories
```

## 3. Daily operations

```bash
sudo service postgresql start        # after every reboot — services do NOT auto-start
cd ~/kingdom
uv run kingdom-api                   # API http://127.0.0.1:8000 (docs /docs); Ctrl+C to stop
uv run kingdom-mcp                   # MCP server over stdio (Claude Code launches this)
uv run pytest                        # full suite (in-memory SQLite, no Postgres needed)
uv run ruff check . && uv run mypy   # lint + types
claude                               # Claude Code session; approve the `kingdom` MCP server
```
The API/MCP servers are FOREGROUND processes — they hold the terminal until Ctrl+C.
Use a second terminal tab, or stop the server, before running other commands.

## 4. Git & GitHub (single clean SSH key)

```bash
# After a reboot the ssh-agent is empty and the key has a passphrase — reload it:
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
ssh -T git@github.com                # expect: Hi TechCorp25!

git push                             # remote + tracking already configured
```

Identity (set once; commits must use the email on the TechCorp25 GitHub account):

## 5. Migrations

```bash
uv run alembic revision --autogenerate -m "add <entity>"
uv run alembic upgrade head
uv run alembic downgrade -1
uv run alembic current               # show applied revision
```
Review autogenerated migrations before applying. Constraint names follow the
convention in `src/kingdom/models/base.py` so diffs stay deterministic.

## 7. Backup & recovery (scripts/backup/)

```bash
./scripts/backup/snapshot-repos.sh                   # bundles + worktree archives
./scripts/backup/verify-and-delete.sh <snapshot-dir> # DRY RUN: verify + preview
./scripts/backup/verify-and-delete.sh <snapshot-dir> --confirm   # delete verified sources
```
Recovery:
```bash
git clone <name>.bundle restored-name                # full history incl. unpushed commits
tar xzf <name>-worktree.tar.gz -C restored-name      # uncommitted + untracked files
tar xzf <name>-full.tar.gz                           # non-git folders
```
Snapshots are gitignored (binary archives don't belong in the repo) and live inside
~/kingdom — copy important ones to /mnt/chromeos/MyFiles to survive a container wipe.

## Lessons learned (this environment's gotchas)

- **Crostini services don't auto-start.** After reboot: `sudo service postgresql start`.
  Use `service`, never `systemctl`.
- **Keep the workspace on native disk.** ~/kingdom is btrfs; venvs and git need real
  symlinks/inodes the /mnt/chromeos/* (9p/FUSE) bridge can't provide. Reading a zip
  from /mnt/chromeos to extract is fine; building/working there is not.
- **GUI extraction drops dotfiles.** The ChromeOS Files app hides files starting with
  `.` — extract zips from the terminal so .mcp.json, .env.example, .gitignore arrive.
- **Browser downloads strip the executable bit.** `chmod +x` scripts after saving,
  or run them via `bash script.sh`.
- **Account key vs deploy key.** `ssh -T git@github.com` greeting tells you which:
  a USERNAME (e.g. "Hi TechCorp25!") = an account key that can push to all your repos;
  a REPO name (e.g. "Hi org/repo!") = a deploy key locked to that one repo and useless
  for anything else. Kingdom uses ONE account key: ~/.ssh/id_ed25519, titled
  "claude-kingdom" on GitHub, authenticating as TechCorp25 over plain github.com.
- **HTTPS git remotes fail to push.** GitHub killed password auth; always use the SSH
  remote (git@github.com:...), never https://github.com/...
- **Set a real git author email.** A placeholder email means commits don't link to your
  GitHub account. Fix with `git commit --amend --reset-author` after correcting config.
- **Push before you duplicate.** Unpushed local commits were the root cause of the five
  stale MAPS copies. Always `git push` before cloning/copying a repo elsewhere.
- **.env survives a zip overwrite.** Extracting the build over ~/kingdom ships
  .env.example, not .env. After a stack change: `cp .env.example .env`, then reset
  DATABASE_URL (must be the +asyncpg driver).
- **uv re-syncs to the system Python.** If `uv run` rebuilds .venv (e.g. Python 3.14
  detected), that's normal; `uv sync` restores the kingdom-mcp console script.
